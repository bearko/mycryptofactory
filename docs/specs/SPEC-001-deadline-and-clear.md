# SPEC-001 — 期限 8 年・クリア（工房 Lv.5）・途中の節目

| 項目 | 内容 |
|---|---|
| 状態 | Approved（作者の決定 2026-10-16・Issue #94、提案の確認 2026-10-17） |
| 関連 | Issue #94、bearko/MyCryptoPortfolio の ROADMAP 2 章・SPEC-002 3.9（総合スコア）・INTEGRATION.md 3.4（RTA）、SPEC-002（セーブ）、SPEC-003（RTA） |

## 1. 背景

いまのコードは 10 年で終わり（`triggerEndgame10y`。2028/12/1 で発火）、何をもってクリアとするかがない。bearko.games の RTA・総合スコアの区切りにするため、期限・クリア・途中の節目を決める。

## 2. 決めたこと

| 項目 | 決定 |
|---|---|
| 期限 | **8 年 = 384 週**。2018 年 12 月 1 週に始まり、**2026 年 11 月 4 週の終わり（2026/12/1 になった瞬間）**で期限 |
| クリア | **期限内に工房 Lv.5 に達すること** |
| 途中の節目 | **各年の終わり**（開始から 48 週ごと。8 年目の終わり = 期限）と、**工房 Lv.2〜4 に達した瞬間** |
| 期限までに Lv.5 に届かなかったとき | ゲームオーバーにしない。成績を出して終え、そのあとも遊べる（いまの 10 年エンドと同じ流れ） |
| 50 年エンディング | 残す（8 年のあとも遊ぶ人の最後の区切り。スコアには入らない） |
| 総合スコア | **期限の時点で止める**（期限のあとは送らない）。Lv.5 までの週数は必ず 384 以下になるので、式は `factory.v1` のまま |

## 3. 仕様

### 3.1 純ロジック（`js/factory-goal.js`）

DOM に触れない純関数だけを置き、`tests/goal.test.mjs` でテストする。

| 名前 | 中身 |
|---|---|
| `DEADLINE_WEEKS` | 384 |
| `WEEKS_PER_YEAR` | 48（1 か月 = 4 週） |
| `yearEndMilestone(weeks)` | 開始からの週数がちょうど 48 の倍数（1〜8 年）なら `"year1"`〜`"year8"`、それ以外は `null` |
| `levelMilestone(lv)` | Lv 2〜4 → `"lv2"`〜`"lv4"`、Lv 5 → `"clear"`、それ以外は `null` |
| `isWithinDeadline(weeks)` | `weeks < DEADLINE_WEEKS` |
| `splitWeeks(weeks)` | 週数を `{ years, months, weeks }` に分ける（クリア画面の「N 年 M か月」） |
| `remainingTime(weeks)` | 期限までの残り `{ years, months, weeks }`（期限を過ぎたら 0） |

開始からの週数は `js/platform.js` の `weeksSinceStart` を使う（Lv.5 の週数と同じ物差し）。

### 3.2 節目を知らせる 1 か所の関数

```js
reachMilestone(id)   // js/main.js。id は "year1"〜"year8" / "lv2"〜"lv4" / "clear"
```

- 1 つの id は 1 回だけ（`state.milestones = { [id]: 開始からの週数 }` に記録。2 回目は何もしない）
- ここから呼ぶもの：RTA の区切り（SPEC-003）と、年の終わりのお知らせ（通知バナーに「N 年目が終わりました（工房 Lv.X）」）
- 呼ぶ場所：工房レベルアップ（`tryFactoryLevelUp`）と週の進行（`advanceWeek`）の 2 か所だけ。`"clear"` は期限内に Lv.5 になったときだけ呼ぶ
- 時間を止めない（モーダルは開かない）。クリア画面・期限の画面は呼び出し元が開く

### 3.3 クリア

- 期限内に工房 Lv.5 になると、レベルアップのマイのセリフを閉じたあとに **クリア画面** を開く（`openClearView` / `closeClearView`。`pauseTime` / `resumeTime` を対で）
  - 見出し「工房 Lv.5 達成！」、かかった時間（「N 年 M か月（W 週）」）、クラフト数・クエスト攻略数・雇用数・保有 GUM
  - ボタンは「このまま遊ぶ」。閉じると、いままでどおりスポット雇用が続く
- `state.clearedWeeks` に開始からの週数を残す（セーブ・成績で使う）
- 期限を過ぎてから Lv.5 になったときは、いままでどおりのレベルアップだけ（クリア画面・`"clear"` は出さない）

### 3.4 期限（8 年）

- `advanceWeek` で開始からの週数が 384 になった瞬間に 1 回だけ（`state.deadlineTriggered`）`triggerDeadline` を呼ぶ。いまの `triggerEndgame10y` を置き換える
- `reachMilestone("year8")` のあと、総合スコアを止める（最後に通知なしで 1 回送ってから、それ以降は送らない。`state.scoreFrozen`）
- マイのセリフはクリアしたかで変える
  - クリア済み：「8 年間お疲れさまでした！ 工房 Lv.5、達成です。」
  - 未クリア：「8 年間お疲れさまでした！ 工房は Lv.X まで育ちました。」（責めない）
- そのあとはいまの 10 年エンドと同じ：スコア画面（旧ランキング）→ 活動レポート（題は「8 年間 活動レポート」）→「集計はここまでですが、引き続き遊べます」

### 3.5 画面のその他

- ホームの目標バナーに期限までの残りを足す：「目標：工房を Lv.N にしよう！（のこり X 年 Y か月）」。期限のあとは残りを出さない
- タイトル画面の β の注記（「リロードすると初期化されます」）は SPEC-002（セーブ）で直す

### 3.6 確かめるための日付送り（本番の画面には出さない）

- URL に `?debug=1` を付けたときだけ `window.mcfDebug` を作る
  - `jumpWeeks(n)`：暦を n 週進め、期限・年の終わりの判定だけを走らせる（月のイベントは飛ばす）
  - `setLevel(lv)`：工房 Lv を直接変える（節目の判定は通る）
  - `addGum(n)`
- 画面にボタンは置かない。`?debug=1` がなければ何も変わらない

## 4. 受け入れ基準

- [ ] 2026 年 12 月 1 週になった瞬間に期限の流れが 1 回だけ出る（2028 年では出ない）
- [ ] 期限内に Lv.5 になるとクリア画面が出て、「このまま遊ぶ」で続けられる
- [ ] 期限のあと Lv.5 になってもクリア画面は出ない
- [ ] `reachMilestone` は各 id で 1 回だけ記録され、Lv.2〜4・各年の終わりで呼ばれる
- [ ] 期限のあとは総合スコアを送らない
- [ ] ホームの目標バナーに残りの年月が出る
- [ ] 50 年エンディングは今までどおり
- [ ] `?debug=1` なしでは `window.mcfDebug` がない
