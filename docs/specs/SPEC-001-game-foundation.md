## 1. 概要

マイクリ（[MyCryptoHeroes](https://www.mycryptoheroes.net/)）の経済圏をモデルに、初心者→トッププレイヤーの体験を圧縮したクラフト経営シム。プレイヤーは工房のマスターとして、受託クラフトから始めて、従業員雇用・工房強化・市場販売へと段階的に成長する。

## 2. 背景と動機

bearko（MCH 3代目ドラゴンキング、MyCryptoTactics 作者）が、原作の経済図を「やればわかる」体験として圧縮したいという要求から発生。フェーズ5（ヒーロー購入）・フェーズ6（大会）は v2 へ持ち越し。

設計方針: **史実をゲームメカに翻訳する**（MCT で確立された方針）。経済図の各ブロックを段階的に解放し、プレイヤーが理想的な成長曲線を体験できるようにする。

## 3. 目標と非目標

### 目標
- 1セッション 20〜40 分で「累計 10,000 GUM 達成 + フェーズ4 解放」を体験できる
- フェーズ1〜4 を順に開放、各フェーズで新しい意思決定が増える
- 物理エンジン・バックエンド・ウォレット連携なしでローカル完結

### 非目標
- フェーズ5（ヒーロー購入：レアリティ階層）— v2 へ
- フェーズ6（大会：自動戦闘＋ハイプシステム）— v2 へ
- マルチプレイ・対人要素
- 実 NFT との連携

## 4. スコープ

### 含む
- 4種カテゴリ（Sword/Helm/Armor/Acc）× 5 Tier の EXT クラフトシステム
- 受託オーダー、自作モード、市場販売
- 従業員雇用（Common 固定）、Lv up、工房 Lv up
- 採集マップ、レア素材出現、価格変動、需要トレンド
- localStorage セーブ（単一スロット `mcf-save-v1`）

### 含まない
- レア度ヒーロー（Uncommon 以上）
- 大会・自動戦闘
- マルチセーブ、難易度選択、実績
- BGM／SE 以外の演出（パーティクル等）

## 5. 契約と挙動

### コアループ（1日 = 1ターン）
1. 受注ボード／市場ニュース確認
2. 素材確保（市場購入 or 自前採集）
3. 従業員にクラフト割当 → ミニゲーム実行
4. 納品 / 自作品の値付け陳列
5. 売上・評判の確定 → R&D投資 → 翌日トレンド更新

### フェーズ解放トリガー
| Phase | トリガー | 解放されるもの |
|-------|---------|---------------|
| 1 | ゲーム開始 | 受託クラフト、4 ミニゲーム、素材市場、Day 遷移 |
| 2 | 累計 1,000 GUM | 雇用、従業員 Lv up、工房 Lv up、スタミナ管理 |
| 3 | 工房 Lv2 + 従業員3人 | 高 Tier 受注、競合 NPC、入札判定、ニュース UI |
| 4 | 累計 10,000 GUM | 採集マップ、レア素材、自作モード、ショーケース、売却シミュレーション |

### 勝利・敗北
- **真エンディング**: フェーズ4 解放（v2 では Legendary 大会優勝）
- **敗北**: GUM<0 が3日連続 ＆ 売却可能在庫なし
- **救済**: 残金100GUM以下で「最低保証受託」が出現

### 状態スキーマ
仕様書 v3 §5 / `src/game/types.ts` を参照。

### エラー条件
- セーブデータ破損 → リセットして初期状態
- localStorage アクセス不可（プライベートブラウジング等）→ メモリ上で動作、リロードで失う

### 互換性
- セーブキー `mcf-save-v1` を Phase 1〜3 で使用
- Phase 4 (SCRUM-32) で `mcf-save-v2` へ移行（`unlockedFeatures` を Set に）

## 6. 非機能要件

- 想定解像度: 1024px+ (PC専用、モバイル対応は v2)
- ビルドサイズ目安: ≤ 200 KB gzip
- Vitest によるロジックテスト必須（クラフト判定・経済計算・需要算出）
